# 房間、對話與卡片製作說明

這份說明給用 Tiled 做房間、用試算表寫對話的組員。程式不需要改動：房間是 `public/assets/maps/` 下的 Tiled 檔，章節的房間怎麼接在一起寫在 `content/chapters/` 的一個 JSON 檔，對話寫在 `content/dialogue/` 的 CSV 檔。每一種檔案都有檢查腳本，錯誤會用中文指出檔名與位置。設計依據是設計文件第 13.2 與 13.3 節；說明與設計文件不一致時，以設計文件為準。

## 做一間房

先安裝 [Tiled](https://www.mapeditor.org/)，再用它開啟專案根目錄的 `body-inc.tiled-project`。物件類別（Door、NPC、Bed 等）與地圖屬性會以下拉選單或勾選框出現，不必背屬性名稱。

新房間從範本複製。`public/assets/maps/_template/` 有四份範本，依房間所屬的世界挑選：`room-lobby.tmj`（大廳）、`room-warehouse.tmj`（肝醣倉庫）、`room-brain.tmj`（大腦）、`room-liver.tmj`（肝）。把檔案複製到 `public/assets/maps/<章>/` 並改名，章是資料夾名稱，房間名稱只用小寫英文、數字與連字號，例如 `public/assets/maps/brain/coffee-room.tmj`。範本是標準的 20 × 12 格房間，南牆已開一個 2 格寬的門，並放了玩家出生點（PlayerStart）。範本刻意沒有填 `organ`、`role`、`estSeconds` 三個地圖屬性，沒填就交出去，地圖檢查會失敗。目前只有 1 × 1 的範本；2 × 1 與 2 × 2 的大房間尚未提供範本，需要時請找程式組。

地圖屬性填這幾項：`organ` 是房間所屬的器官，`role` 是房間的用途（combat、puzzle、rest、treasure、transit、core），`estSeconds` 是預估通關秒數，`difficulty` 為 1 到 3。有敵人是「打不掉」的類型時，教學房要在 `tutorialFor` 填那種敵人的 id，詳見設計文件 5.5 節與 13.3 節。

房間畫在兩個圖塊圖層上。`floor` 圖層是地板，只負責好看。`walls` 圖層的每一個非空格都是牆，營運長走不過去，所以地板上的家具不要畫在 `walls` 上，除非它真的要擋路。場景裝飾的做法見 README 的「編輯地圖」。

## 房間裡的物件

物件放在名為 `objects` 的物件圖層。從 Tiled 的類別下拉選單選類別後，只填需要的屬性。下表列出目前有效果的類別；Hazard 目前只檢查格式，放進去不會有任何動作，要等負責的功能完成。

| 類別 | 做什麼 | 要填的屬性 |
| --- | --- | --- |
| PlayerStart | 營運長出生與強制下班（還沒打過卡時）回來的位置，每間房一個 | 無 |
| Spawn | 敵人生成點 | `enemyType` 從下拉選單選；`count` 數量；`respawnSeconds` 擊退後幾秒再出現，0 表示不再出現；`when` 條件式 |
| NPC | 可對話的角色，走近按 E 或 Enter | `npcId`、`dialogueId`（必須存在於對話 CSV）；`npcId` 與 `public/assets/manifest.json` 裡某個角色圖的名稱相同時（例如 `liver`），會自動畫出那個角色，否則畫一個佔位的人形 |
| Trigger | 營運長踩上去就觸發 | `event` 見下段；`eventId`；`once` 預設只觸發一次；`when` 條件式 |
| Door | 房間的門 | `socket` 朝哪個方向；`lock` 鎖的種類與 `lockParam`，見下方「門鎖與開關」；**物件的 Name 欄必填** |
| Switch | 開關（拉桿）或壓力板，用來開 `lock` 為 `switch` 的門，或啟動輸送帶 | `target` 選要開的門或輸送帶；`mode` 是 `toggle`（拉桿）或 `hold`（壓力板）；`cooldownSeconds` 是拉桿變動後多少秒內不接受新的一次（預設 0），見「分岔輸送帶與拉桿冷卻」 |
| Box | 推得動的箱子，佔一整格，見下方「推箱與輸送帶」 | `boxType` 只決定外觀（`crate`、`glucose`、`acetaldehyde`、`food`）；`when` 條件式 |
| Conveyor | 輸送帶，把上面的箱子與營運長往一個方向送，見下方「推箱與輸送帶」 | `direction` 方向（N、S、E、W）；`speed` 是 `slow`、`normal` 或 `fast`；`altDirection` 不是 `none` 時是分岔輸送帶，見「分岔輸送帶與拉桿冷卻」；**必須畫成矩形** |
| Port | 調度口，收下送進來的箱子，收滿就打開一扇門，見下方「調度口」 | `need` 要收幾個箱子；`target` 選收滿時要開的門；`dialogueId` 收滿時開啟的對話，可留空；`accepts` 是 `any` 或只收小包裹的 `parcel`；`openSeconds` 與 `closedSeconds` 都大於 0 時是限時閘門；**必須畫成矩形**，每間房最多一個 |
| Bed | 床 | `bedType` 是 `nap` 或 `sleep`；`requires` 條件式，成立才能用；`unlocks` 是午睡沙發第一次用時順便解鎖的手冊頁代號，可留空；`sleepSeconds` 是就寢床的睡眠進度條要睡幾秒，0 表示躺下立刻結束這一章，見下方「睡眠進度條」 |
| Pickup | 撿得起來的道具，走近按 E 或 Enter | `itemType` 道具種類；`itemId` 見下方「道具與員工手冊」；`when` 條件式 |
| Dock | 報復性宵夜部長的外送口，見下方「報復性宵夜部長與外送口」；箱子從它的中心出發 | 無 |
| EvidenceSlot | 證據牆上掛節點的位置，只用在 `tools/maps/make-wall.ts` 產生的證據牆房間 | `day` 第幾天（1 到 10）；`lane` 是 `upper`、`lower` 或工單板的 `liver`；`order` 同一格裡的第幾個。每天每條軌道要有 3 個、工單板要有 8 個，地圖檢查會數；沒有任何 EvidenceSlot 的房間不受影響 |

Trigger 的 `event` 有七種。`checkpoint` 是打卡機：營運長踩上去時存檔、補滿心，之後強制下班會回到這裡，每次踩上去都算，不受 `once` 影響。站在打卡機旁邊按 E 或 Enter 也能打卡，HUD 會出現互動提示，因為打卡機看起來是個物件，玩家第一個會試的是互動鍵。旁邊同時有道具、NPC 或拉桿時，互動鍵先用那些，打卡機排最後，所以記憶碎片可以緊貼著打卡機擺；已經站在打卡機上時互動鍵不會再打卡，因為踩上去那一刻已經打過了。`clock_advance` 讓章內時鐘前進，`eventId` 填分鐘數，必須是 1 到 4 位數的整數，例如 `20`；留空、寫小數、`1e1` 或文字都會被地圖檢查擋下。`dialogue` 開啟對話，`eventId` 填對話 id。`card` 翻開一張事件卡，`eventId` 填這一章卡組裡事件卡的 id，寫法見下方「卡片」一節。`rescue` 開啟一段急救，`eventId` 填 `content/rescue.json` 裡的 id，見「肝臟工廠與急救」一節。`cutscene` 會通知外層的過場，那個功能完成前沒有反應。`end` 結束這一章，`eventId` 留空，效果與 `sleep` 床相同，用在不以睡覺收尾的章節，例如序章下班打卡，畫面上會畫成一塊淺色地墊，箭頭指向比較近的左右牆，讓玩家知道往哪裡走（電梯 `eventId` 為 `elevator` 的照舊畫成電梯）；它的 `when` 會被完成檢查當成「床的條件」來看，所以章節裡至少要有一張 `sleep` 床或一個 `end` 觸發點。

Bed 的 `nap` 是午睡沙發：時鐘前進 20 分鐘，黏在身上的腺苷全部回到原處，每張床只能用一次。午睡沙發的 `unlocks` 填一個存在於 `content/handbook.json` 的頁面代號，第一次躺下時解鎖那一頁，之後再躺不會重複；大腦章的沙發給〈短暫午睡〉，地圖檢查會確認代號存在；就寢門不看這個欄位。`sleep` 是就寢門：條件成立就結束這一章；章節檔有 `next` 或卡組有章末卡時接著翻章末卡、進下一章，否則回到標題畫面。`requires` 寫成條件式，例如 `caffeine<15`，不成立時床會回應「還睡不著」。條件式只能用 `content/tags.json` 裡的標籤，語法是標籤名、比較運算、驚嘆號否定、逗號表示「且」。`sleepSeconds` 大於 0 的就寢門不會立刻結束這一章，而是先跑一條睡眠進度條，見「胃的攪拌機」一節裡的「睡眠進度條」小節。

NPC、Bed、Trigger、Pickup 可以畫成矩形，也可以只放一個點。放點的時候，遊戲以 1 格大小、置中在那個點上處理。門一定要畫成矩形。

Door 的 `socket` 位置是固定的，檢查腳本會逐一指出放錯的地方：北門在北牆第 9 至 10 欄，南門在南牆（最後一列）第 9 至 10 欄，西門在西牆第 6 至 7 列，東門在東牆第 6 至 7 列。

## 門鎖與開關

設計文件 13.3 節規定房間裡的解謎必須自給自足，跨房間的進度只能靠全域狀態（時鐘、標籤）傳遞，門鎖的規則依此訂定。`lock` 有五種：

| `lock` | 什麼時候打得開 | `lockParam` 填什麼 |
| --- | --- | --- |
| `none` | 一直開著 | 留空 |
| `switch` | 同一間房裡每一個 `target` 指向這扇門的開關都打開時 | 留空 |
| `clock` | 章內時鐘落在開放時段內時 | 時段，例如 `08:00-10:00`；過午夜寫成 `22:00-02:00`，開到午夜寫成 `17:00-24:00`；開始的那一分鐘算在內，結束的那一分鐘不算 |
| `resource` | 條件式成立時，例如咖啡因殘留低於 50 | 條件式，例如 `caffeine<50`，語法與 `when` 相同 |
| `key` | 同一間房裡 `itemId` 等於 `lockParam` 的道具被撿起後；`lockParam` 留空的門永遠不開，用來封住不用的門口 | 鑰匙道具的 `itemId`，例如 `archive-key`；或留空 |

鎖上的門會掛一塊墨藍色鎖牌，圖示分別是鑰匙、拉桿、時鐘與量表，門打開時鎖牌消失；營運長碰到鎖著的門時，會依鎖的種類跳出不同的提示。時鐘與條件式每一刻都重新判斷，所以 `clock` 與 `resource` 的門會隨時間或標籤改變而開關。營運長貼著一扇鎖著的門等待時，門一打開就會直接走過去，不必退開再走一次。

Switch 有兩種。`toggle` 是拉桿：走近按 E 或 Enter 可以來回切換；用釘書機射中也會把它打開，但射擊不會把它關上，避免按住連射時開關一直跳動。拉桿可以放在牆面上，例如北門旁邊的牆面，釘書針會先打到拉桿才被牆擋下。拉起的拉桿會一直維持，離開房間再回來、強制下班回到打卡機都一樣，打卡時也會一起存檔，因為解開的機關就保持解開。`hold` 是壓力板：營運長站在上面，或有箱子停在上面時才算開，兩者都離開就恢復。壓力板本身不會被記住，但停在上面的箱子會，見下方「推箱與輸送帶」。一扇門可以有好幾個開關指向它，必須全部打開門才開。開關只能指向 `lock` 為 `switch` 的門或輸送帶，`lock` 為 `switch` 的門也至少要有一個開關指向它，否則地圖檢查會指出。放在 `variant:` 圖層裡的開關只在那個變體出現時存在，變體沒出現時，只靠它開的門就打不開。

要注意，營運長無法一邊站在壓力板上、一邊走進遠處的門，所以只靠壓力板開的門，要房間裡有箱子可以壓住壓力板才走得過去；地圖檢查判斷房間能不能走到時，只把放在 `objects` 圖層、`when` 留空的箱子算進去。灰盒章節的 `greybox/greybox-room` 北門與 `greybox/lock-hall` 示範了拉桿、時段與條件式三種鎖，可以用 `?room=greybox/lock-hall&tags=caffeine:100` 看到條件式的門關上；`greybox/archive` 的西門示範鑰匙鎖。

`key` 鎖的鑰匙一定要和門在同一間房，這也是設計文件「解謎自給自足」的要求。鑰匙可以是任何種類的道具，建議用 `file`（一份文件），因為它沒有別的效果。鑰匙必須放在 `objects` 圖層、`when` 留空：放在變體圖層或加了條件，換一組狀態再進房時鑰匙會不見，已經打開的門又會鎖上，所以地圖檢查會擋下。`lockParam` 寫了名字卻找不到同名道具，地圖檢查也會指出。鑰匙撿起來之後門就保持打開，離開再回來也一樣。

## 推箱與輸送帶

Box 是推得動的箱子，佔一整格，可以畫成矩形或只放一個點，遊戲取它中心所在的那一格。營運長正面貼著箱子，只按一個方向鍵持續推約六分之一秒，箱子就往那個方向滑一格；一直按著會一格接一格推下去。斜著按、同時貼著兩個箱子、正在閃身、受傷硬直或蓋駁回印章時都推不動。箱子不能推進牆、另一個箱子、門、NPC、床、道具、觸發區所在的格子，也不會壓到營運長、敵人或敵人出現的位置（敵人重生、重組、強制下班後都會回到那裡）。箱子對營運長、敵人與釘書針都是實心的。設計文件 13.3 節的物件類別沒有箱子，這是為了第二章的葡萄糖箱與肝臟章的乙醛箱新增的類別。

箱子停在壓力板上時，壓力板就算踩下，滑過去的途中不算。這是讓營運長離開壓力板、走進遠處的門的方法，灰盒章節的 `greybox/loading-dock`（從儲藏室東門或大廳東門進去）示範了整套流程：把板條箱往西推上輸送帶，拉起牆上的拉桿，輸送帶把箱子送到壓力板上，西門打開。

Conveyor 是輸送帶，佔它矩形範圍內的格子（以格子中心是否在矩形內判斷）。沒有任何開關指向它時一直運轉；有開關指向時，要每一個開關都打開才運轉，停下時箭頭變暗。運轉中的輸送帶把停在上面的箱子往 `direction` 一格一格地送，送一格要花的時間是 `slow` 一秒、`normal` 半秒、`fast` 四分之一秒（每秒 1、2、4 格），前方擋住時就等著，前一個箱子還沒完全離開的格子也算擋住，所以一排箱子在輸送帶上會隔一格前進；送到輸送帶盡頭的下一格後箱子停下。被輸送帶運送中的箱子，在抵達之前原本那一格也算實心，營運長不會走進去。營運長腳下那一格在運轉中的輸送帶上時，會以同樣的速度被帶著走。營運長最快每秒走 4.5 格，所以平常逆著任何一種輸送帶走都前進得了，只是比較慢；但按住射擊（每秒 3.15 格）、舉著公文夾格擋（每秒 1.8 格）或肝臟章的暈眩（每秒 3.825 格）時，`fast` 輸送帶會比營運長走得快，逆著走反而會被往後帶，可以當作關卡的難點來用。身上黏著腺苷做不到這點：黏一層、兩層時營運長仍有每秒 4.275、4.05 格，黏到第三層就立刻強制打盹。輸送帶不會帶動敵人。

箱子的位置會記住，規則是「解開的機關保持解開」：離開房間再回來、強制下班或讀取打卡點時，停在壓力板上的箱子留在原地，其餘箱子回到地圖上的位置。所以把箱子推進牆角卡住時，出房間再進來就能重來。強制下班和拉起的拉桿一樣，不會把已經壓在壓力板上的箱子退回去。打卡也會存下箱子的位置，讀取打卡點時照同樣的規則擺回。箱子要擺回的位置剛好被營運長或另一個箱子佔住時，會改放到最近的空地板上，但不會放在調度口上，否則箱子沒被推就被收下。`when` 在進房時判斷一次，不成立時這一趟箱子不在房間裡。

地圖檢查會指出箱子放在牆上、兩個箱子放在同一格、箱子壓在門／NPC／床／道具／觸發區／調度口上、箱子壓到出生點、從門進房時營運長站的位置或 Spawn 敵人出現的位置，以及輸送帶畫成點而不是矩形。兩個物件的條件不可能同時成立時，例如一個箱子的 `when` 是 `breakfast`、另一個是 `!breakfast`，它們永遠不會在同一趟出現，所以放在同一格不算衝突；判斷看的是箱子、道具與 Spawn 自己的 `when`，以及所在變體圖層的 `when`。觸發區的 `when` 只決定它會不會觸發，觸發區本身一直都在，所以仍然算衝突。

箱子可以壓在拉桿上。這時釘書針會被箱子擋下，打不到下面的拉桿，要先把箱子推開。

## 調度口

Port 是調度口，序章倉庫用它收葡萄糖箱。箱子停在調度口的任何一格上時就被收下（`accepts` 為 `parcel` 的調度口只收小包裹，見下方「胃的攪拌機」），從房間消失；推動時滑過的途中不算，要停下來才算。輸送帶每送一格箱子都會停一下，所以輸送帶帶著箱子經過調度口時，箱子會被收下。收下的箱子會記住，離開房間、強制下班或讀取打卡點都不會吐回來，和拉起的拉桿一樣。調度口上會顯示「已收／`need`」，收滿時變成藍色，`target` 指的門打開，`dialogueId` 有填的話接著開啟那段對話，對話裡可以寫收滿之後的效果，例如補血糖或解鎖手冊頁。這段對話只開一次；收滿的那一刻營運長剛好倒下時，對話會在回到打卡點之後、下一次待在調度口所在的房間時開啟，不會就此消失。

`openSeconds` 與 `closedSeconds` 都大於 0 的調度口是限時閘門，用來做胃章的小腸閘門（設計文件 7.5 節的「攪拌機節奏」）。進房後閘門先關 `closedSeconds` 秒，再開 `openSeconds` 秒，一直循環。每次進房、強制下班回到打卡點或繼續遊戲，都從關著重新算；還沒打過卡時的強制下班不會重新算。關著的閘門蓋著灰色百葉，什麼都不收，箱子也推不上去、滑不上去：滑上閘門要在閘門開著時滑完，所以快關門時輸送帶與推箱也不會把箱子送上去，輸送帶會把箱子停在閘門前一格排隊，等閘門打開才一個接一個送進去。只收小包裹的閘門開著時也不讓別種箱子上去，免得食物箱停在百葉底下，把後面的隊伍一直擋住。營運長受擊時整個房間短暫停格（hit-stop），閘門的倒數也一起停，所以算好在開著時滑完的箱子，中途被停格打斷也照樣趕得上。閘門佔哪些格子和輸送帶一樣以格子中心為準。閘門上方顯示已收的數量與倒數，例如「1/3　12 秒後開」「1/3　還開 5 秒」，開與關各有一聲提示音。收滿之後閘門一直開著，不再倒數也不再出聲。錯過開啟時間只是要等下一輪，已經收下的不會吐回來。兩個數字只填一個時地圖檢查會指出（`port-timing`）。灰盒測試房 `stomach/mixer-lab` 的閘門先關 20 秒、再開 8 秒，出口到閘門只有兩格輸送帶，閘門關著時第三個小包裹就要留在攪拌機裡。

調度口在門鎖的規則裡就是一個開關，收滿時打開，所以 `target` 和 Switch 一樣，只能指向 `lock` 為 `switch` 的門或輸送帶；同一扇門如果還有拉桿或壓力板指向它，要全部成立門才開。章節檢查把調度口指向的門算成通路，因為 `need` 已經保證房間裡的箱子夠用。調度口必須畫成矩形，每間房最多一個；第二個調度口會被地圖檢查指出。調度口佔哪些格子和輸送帶一樣以格子中心為準，所以矩形至少要蓋住一格的中心，其中至少一格是地板；太小而蓋不到任何格子中心（`port-shape`），或蓋住的格子全是牆（`port-wall`），箱子都停不上去，地圖檢查會指出。`need` 至少是 1，而且不能多於房間裡放在 `objects` 圖層、`when` 留空的箱子數，否則房間永遠無法收滿，地圖檢查會指出差幾個。箱子不能一開始就放在調度口上。

設計調度口的房間時，要確認沒有任何一推會讓箱子永遠卡住。箱子推到牆邊之後，就只能沿著牆推，推進牆角就再也推不動；出房間再進來雖然能讓箱子回到原位，但玩家不一定想得到。序章倉庫（`prologue/warehouse`）的做法是讓輸送帶沿著東、南、北三面牆繞一圈，把箱子送進西北角的調度口：箱子被推到東、南、北牆邊都會上輸送帶，被推到西牆邊則可以沿著西牆往北推進調度口，所以每一推都還有路。地圖檢查看不出這種卡死，要靠試玩確認；序章的倉庫就是在瀏覽器試玩時才發現第一版會卡住而重新設計的。

## 胃的攪拌機

胃章（設計文件 7.5 節）的攪拌機是 Mixer 物件，畫成矩形，蓋住的格子是投料口，以格子中心為準。投料口是地板，營運長可以走上去，箱子可以推上去或由輸送帶送上去。`boxType` 為 `food` 的食物箱停在投料口上就被收進攪拌機，從房間消失；其他種類的箱子停在上面不會被收。收進去的箱子依自己的 `portion` 計時：`small` 15 秒、`normal` 20 秒、`large` 40 秒，這是設計文件的數字，「油炸物消化較久」要等待查證第 14 項完成才會進數字。攪拌機裡的箱子同時計時，時間到的箱子變成小包裹，從 `outlet` 那一側正中間外面的一格（出口）吐出來，而且只會吐在出口上。出口被占住時（前一個小包裹還沒被帶走、有箱子或有人站在上面、或出口是限時閘門，而且下一刻閘門是關著的，因為小包裹要放下的下一刻才會被收），做完的小包裹留在攪拌機裡等，照樣佔著容量；這時再送食物進去，就可能塞滿卡住，連做完的小包裹也變回食物箱吐出來。這是設計文件 7.5 節「吃太快太多只會塞車」的規則，出口接的輸送帶越短、閘門關得越久，就越要算好投料的時機。兩個箱子同時做完時，先放進去的先出來。攪拌機上方的格子顯示容量與每一箱的進度。

攪拌機最多同時處理 `capacity` 箱（預設 3，Boss 戰用 4），Boss 丟來的加大份算 2 箱，手推的箱子不論份量都算 1 箱。滿了之後再送一箱進去就卡住：攪拌機裡的箱子、這一箱，以及投料口上其他還沒收的食物箱，全部原樣吐回投料口附近的空地板上，進度歸零，畫面提示「放不下了！全部退回去！」。吐出的箱子不會落在投料口、調度口、冷藏庫或任何輸送帶上（輸送帶停著也一樣），所以不會馬上又被收進去或被送回去。

小包裹是 `boxType` 為 `parcel` 的推箱，只由攪拌機產生，地圖上畫不出來。它和其他推箱一樣推、一樣被輸送帶帶走。調度口的 `accepts` 選 `parcel` 時只收小包裹，用來做小腸閘門；食物箱停在這種調度口上不會被收。只收小包裹的調度口要求房間裡有攪拌機（`port-parcel`），`need` 只算房間裡一定在場的食物箱。

攪拌機裡的東西只屬於這一趟：離開房間、強制下班或讀取打卡點時攪拌機清空，裡面的箱子回到地圖上的原位。攪拌機放到地上的箱子（小包裹與卡住時吐出的箱子）和推過的箱子一樣記住位置，下次進房時變回食物箱，照推箱的規則回到原位；停在壓力板上的會留在壓力板上。已經送進調度口的小包裹和其他調度口一樣記住。地圖檢查會指出攪拌機畫成點或太小（`mixer-shape`）、蓋住的格子有牆（`mixer-wall`，投料口每一格都要是地板）、放在變體圖層（`mixer-variant`）、一間房超過一台（`mixer-multiple`）、出口那一格是牆或在地圖外（`mixer-outlet`）、門／NPC／床／道具／觸發區／調度口／開關壓在投料口上（`mixer-blocked`）、壓在肝臟工廠的收貨區上（`dock-blocked`），以及箱子一開始就壓在投料口上。灰盒測試房是 `stomach/mixer-lab`，由 `tools/maps/make-stomach.ts` 產生，用 `?room=stomach/mixer-lab` 開啟。

### 睡眠進度條

`bedType` 為 `sleep` 的床把 `sleepSeconds` 設為大於 0 時，營運長躺下後不會立刻結束這一章，而是在畫面底部出現睡眠進度條，畫面變暗（熄燈）。睡著時按鍵沒有作用，營運長不會動，床邊的輸送帶也帶不走睡著的營運長；進度條走滿 `sleepSeconds` 秒時，這一章照一般就寢門的方式結束，歸檔也照樣計算。`requires` 與一般就寢門相同，不成立時床回應「還睡不著」，進度條不會開始。

有兩件事會把營運長吵醒（半夜醒來）。其一是同一間房的攪拌機：睡著期間攪拌機連續處理食物滿 20 秒，就響一次警報，提示「胃還在加班，半夜醒來了」；攪拌機手上沒有正在處理的箱子時（處理完、只等出口有空位的小包裹不算），這 20 秒就重新算，所以處理時間 15 秒的小份不會吵醒人，加大份會。其二是任何落在營運長身上的攻擊：扣心的攻擊、黏上來的腺苷、敬酒波與能量飲料罐都算，因為睡著的營運長閃不開，不叫醒的話腺苷會一路黏到強制打盹；這時只有提示，不響警報。挨打剛好落在進度條走滿的那一刻時，算被打醒，進度條停在差一點滿的地方，再躺下就滿；那一下若是致命的，照強制下班處理，這一章不會結束。醒來後進度條停在原處，不會倒退，營運長可以自由走動。箱子一旦進了攪拌機就拿不出來，想讓它安靜只能等它處理完，或再塞到卡住讓它把箱子全部吐回來。回到一張 `sleepSeconds` 大於 0 的就寢床旁按 E 或 Enter 就再躺下，進度條從停下的地方繼續，長度仍照第一次躺下那張床的秒數，警報的 20 秒也重新算；醒著時去躺一張沒有睡眠進度條的就寢床，則照一般就寢門立刻結束這一章。這對應設計文件 7.5 節「只做中斷，不做睡不著」：證據只支持睡前進食與半夜醒來有關，而且屬於初步研究，所以醒來只讓進度暫停，進度條不會因此倒退或無法入睡。

「深夜時段」目前就是指睡著的期間：章內時鐘以小時為單位前進，玩家不一定在某個鐘點附近才上床，所以警報只在睡眠進度條跑著時才算，清醒時攪拌機不會響。進度條和攪拌機一樣只屬於這一趟，離開房間、強制下班或讀取打卡點就作廢，下次重新躺下從頭開始。醒來的次數會記在進度條上，之後章末的結案報告可以用它，目前還沒有讀。午睡沙發（`nap`）設了 `sleepSeconds` 時地圖檢查會指出（`bed-seconds`），因為只有就寢床有進度條。灰盒測試房是 `stomach/night-lab`，從 `stomach/mixer-lab` 送滿三個小包裹後打開的東門進去，也可以用 `?room=stomach/night-lab` 直接開啟：房裡的床要睡 30 秒，把加大份的箱子送進攪拌機再上床就會被吵醒。這間房沒有沿牆的輸送帶迴圈，箱子推進死角就只能出房重來，不過床不需要任何箱子，所以不會卡關。

### 冷藏庫

冷藏庫是 ColdStore 物件，用來做胃章謎題三「深夜加班」（設計文件 7.5 節）：攪拌機會在睡覺時把人吵醒，所以睡前與其把食物箱送進攪拌機，不如推進冷藏庫，留到明天當早餐，對應「請室友幫帶一份，明天當早餐」的折衷。冷藏庫畫成矩形，佔哪些格子和輸送帶一樣以格子中心為準，沒有屬性。`boxType` 為 `food` 的食物箱停在冷藏庫的任何一格上，就被冷藏起來，從房間消失，畫面提示「冷藏起來，明天當早餐」；推動或輸送帶送著滑過的途中不算，要停下來才算。其他箱子（一般箱子、小包裹）停在上面就和停在地板上一樣。冷藏的箱子和送進調度口的箱子一樣記住，離開房間、強制下班或讀取打卡點都不會回來，這一章裡就不再出現；但它不算進任何調度口的數量，所以冷藏太多食物，調度口可能永遠收不滿，排房間時要留意。箱子進了攪拌機就拿不出來，只有塞到卡住讓攪拌機把箱子全部吐回來，才能再推去冷藏。遊戲自己不會把箱子放上冷藏庫：卡住時吐出來的箱子不會落在上面，重新進房時箱子也不會被放在上面。輸送帶則照常運作，盡頭接著冷藏庫的輸送帶會把食物箱送進去冷藏，睡著時也一樣；這是排房間的人刻意的安排，不想讓輸送帶代替玩家決定時，盡頭就不要接冷藏庫。一間房可以有多個冷藏庫；放在變體圖層的冷藏庫只在那個變體成立的那一趟出現，已經冷藏的箱子不受影響。冷藏的箱子目前只是離開這一章，章末的結案報告與隔天早上的早餐之後才會讀它。

地圖檢查會指出冷藏庫畫成點或太小（`cold-shape`）、蓋住的格子全是牆（`cold-wall`）、門／NPC／床／道具／觸發區壓在上面（這些物件上停不了箱子）、壓力板壓在上面或和調度口、攪拌機投料口、輸送帶佔到同一格（兩者會搶同一個箱子），這兩種都是 `cold-blocked`；永遠不會同一趟出現的兩個變體物件不算重疊。另外也會指出壓在肝臟工廠的收貨區上（`dock-blocked`），以及箱子一開始就放在冷藏庫上（`box-blocked`）。灰盒測試房 `stomach/night-lab` 的南側（第 6 至 8 欄、第 9 至 10 列）有一個冷藏庫：把兩箱食物推進去，攪拌機就不會在睡覺時運轉。

### 宵夜外送員

宵夜外送員（設計文件 7.5 節，`courier`）是胃章的第二種一般敵人，在 `content/enemies.json` 是 `defeatable`、archetype 為 `courier`、performance 4。他不傷人，也不朝營運長丟東西：站在出生點，每隔 8 秒、而且有輸送帶接得住時，舉起一箱訂單（tier 1 預警 0.5 秒，頭上出現驚嘆號泡泡），把它丟上輸送帶的起點，臉朝著那條帶子而不是營運長。訂單是 `boxType` 為 `food`、`portion` 為 `normal` 的食物箱，沒有 Tiled 物件，id 是 -1000000 往下數，只屬於這一趟（強制下班時和攪拌機裡的東西一樣消失，編號繼續往下數）。「油炸物消化較久」同樣等待查證第 14 項，所以訂單不另外加時間。

設計文件說兩種處理都合法。放行：輸送帶把訂單送進攪拌機，攪拌機照 20 秒消化，佔一格容量，睡著時照樣讓警報響；消化完不產生小包裹，所以不會被小腸閘門算進去，只有玩家自己餵的食物箱才做得出小包裹。訂單送進去讓攪拌機滿了的話，一樣會卡住，連玩家餵的箱子一起吐回來，吐出來的訂單仍是食物箱。退貨：印章落地時，半徑內的訂單從房間消失，章節在 `returned_orders` 標籤加 1，原因記成 `choice:return.courier`。這個標籤是「退貨幾次」的計數，設計文件寫的是外層社交 −1，而標籤不能是負數，所以由外層之後把每次退貨讀成 −1；目前沒有程式讀它，除了因果紀錄之外只有畫面提示「退貨，外送員記下一筆」。印章半徑內的外送員本人也吃那一下，4 點 performance 一下結案，這是印章對一般敵人的既有規則。攪拌機裡的訂單和送出去的小包裹不在退貨範圍內。

他只丟在「最近的一條在跑的輸送帶」的起點：起點是順著帶子方向最上游的那一格，起點要是空地板（沒有箱子、人、門或其他固定物件），也不能是攪拌機投料口或調度口，否則訂單會被當場吃掉；開關關著而停下來的帶子不算在跑。起點被占住、或這一趟他的訂單已有 2 箱在地板上（輸送帶沒人清、箱子堆在帶子盡頭），他就不起預警、站著等，所以不會被洪水淹沒，也不會丟出沒有落點的訂單。舉起訂單到真正丟出去之間，場上的狀況可能變了，所以落地的那一刻會再檢查一次：同一刻有好幾位外送員一起丟時，全部加起來也只收 2 箱，編號小的外送員先落地，其餘的作廢；起點在這一刻剛好被走過去的敵人踩住，那一箱也作廢，不會疊在敵人身上。一間房有外送員就必須有一條不在變體圖層的 Conveyor（`courier-belt`），也不能放在有肝臟工廠產線的房間（`courier-factory`），因為工廠把所有負的 id 都當成乙醛箱。訂單不會被冷藏庫收，停在冷藏庫上就和停在地板上一樣：目前的冷藏只認地圖上畫的食物箱。

他和糖業務員一樣可以結案：章節檔 `closedCases` 把 `courier` 對到標籤 `courier_closed`，放他的 Spawn 寫 `when` 為 `!courier_closed`，結案之後每次進房都不會再出現。設計文件沒有指定他掉手冊頁，所以 `caseDrops` 沒有他。灰盒測試房 `stomach/night-lab` 在入口的輸送帶起點旁邊有一位：睡前的 30 秒裡，放行的訂單會一箱一箱送進攪拌機，讓警報響；在輸送帶旁蓋印章則退貨。他的外觀暫時借用傳單人員的圖。

### 食物塊

食物塊是 Chunk 物件（設計文件 6.2 與 7.5 節），胃章的堵路障礙：畫成矩形，蓋住的格子（以格子中心為準）在遊戲中和牆一樣是實心的，營運長、敵人、箱子和飛行物都過不去；胃物流主管的酸液在它上面躺滿 1.5 秒，它就融掉，那些格子變成地板，之後整章都不再出現，強制下班也不會長回來。1.5 秒是等試玩調整的暫定值（`CHUNK` 在 `src/core/stomach/chunks.ts`），設計文件沒有給時間。酸液是固定的長方形，所以只要酸液蓋到食物塊的任何一格，整塊食物塊在第 90 個 tick 一起融掉；酸液沒蓋到的食物塊不受影響。

食物塊不是 Tiled 的牆圖層，載入房間時就算進格子裡，所以不能放在變體圖層（`chunk-variant`）；它蓋住的格子本來必須是地板，不能有牆、收貨區或超出地圖（`chunk-wall`，否則融掉會把牆一起打通）；兩塊食物塊不能共用格子（`chunk-overlap`）；也畫成矩形才算數（`chunk-shape`）。出生點、NPC、道具、床、開關、Spawn、門和調度口、攪拌機、冷藏庫、輸送帶、第二產線壓在食物塊上會被指出（`chunk-blocked`），因為站在實心格子裡走不到、蓋格子的物件收不到箱子；觸發區可以跨過，Box 畫在上面則是 `box-wall`。章節的 `partner` 不是 `logistics` 的話，章節檢查會指出房間裡的食物塊，因為只有他的酸液融得掉，玩家永遠過不去。

融掉的食物塊記在章節的 `fired` 裡，鍵是 `房間#dissolved.物件id`，帶有字母，所以不會被當成道具、箱子或冷藏的物件 id；它的畫面是占位的米黃色塊，酸液躺在上面時逐步變綠，融掉的瞬間發出 `chunkDissolved`（聲音 `unlock`，提示「食物塊被融掉了，路通了」）。灰盒測試房 `stomach/night-lab` 的東北角有一個 2 格見方的小隔間，裡面放了一箱多出來的食物，南邊和西邊各有一塊食物塊擋著：站在隔間南邊兩格處朝上吐一口酸液，兩塊會一起融掉。

### 報復性宵夜部長與外送口

胃章的 Boss 報復性宵夜部長（設計文件 7.5 節，敵人 id `snack`，檔案 `content/bosses/snack.json`）站著不動，輪流叫房間裡的外送口：每次先舉起 0.5 秒的一級預警，再從那個外送口丟出一箱食物，箱子沿直線飛向攪拌機投料口的中心。外送口是 `Dock` 物件，畫成矩形或放一個點都行，箱子從它的中心出發；部長依物件編號從小到大輪流叫，叫完最後一個回到第一個，所以畫的順序就是他叫的順序。第一箱在戰鬥開始 3 秒後預警，之後每 4 秒一箱。這些秒數、飛行速度（每秒 5 格）與每箱 20 秒的消化時間都是設計文件沒有給的暫定值，寫在 `content/bosses/snack.json` 的 `notes`。

沒人攔的箱子飛到投料口就被攪拌機收進去，消化 20 秒，不留包裹（和宵夜外送員的訂單一樣，只占容量）。攪拌機的容量由房間裡 Mixer 的 `capacity` 決定，Boss 戰寫 4。每 4 秒一箱、每箱 20 秒，所以不攔的話第五箱會在第一箱消化完之前到達：收到第五箱時攪拌機抗議（胃抗議），裡面的箱子全部作廢，並在投料口中心張開一個半徑 3 格的範圍。它是三級預警，從落地那一刻起預警 1.4 秒（含落地那一刻共 84 個 tick）才生效，生效 8 個 tick，傷害一顆心，所以預警最後一個 tick 按閃身就躲得掉。這個範圍目前只對營運長判定傷害，部長和其他敵人即使站在圈內也不受影響（所有範圍攻擊的判定都只看營運長），而設計文件說它「不分敵我」，要不要讓它也傷到敵人留待試玩決定。畫面上它畫在地上（虛線圈加斜線填滿），這是三級預警不畫在地上的例外，因為它的中心是投料口，不是 Boss，沒有提案書可以當預警。

營運長可以站到箱子的路徑上用公文夾擋：一般的擋住（格擋）箱子就消失，不進攪拌機；在護擋最前面 9 個 tick 內（退件）則把箱子彈回去，以原來的速度飛向部長（飛行距離一定夠到他，不論在哪個外送口附近退件），打中時扣掉他 `returnDamage`（20）的預算，這是一般攻擊中唯一能傷到他的方式：一般的訂書針和公文夾的揮擊都打不動他，只發出 `snackShrugged`（彈開的音，不扣預算）；集滿量表的駁回印章則和其他 Boss 一樣扣 40。他的預算 100，所以只靠退回的話，五箱就結案。沒擋的箱子打中營運長是一級攻擊，半顆心；閃身穿過去不會受傷，但箱子照樣飛到投料口被收進去。部長結案時，還在空中的箱子跟著消失。

他的預算降到 `stage2.budget`（60，也就是退回兩箱）以下時進入第二階段「加大份量」：如果他正在預警，那一箱照常以一般份丟出，丟完的下一個 tick 才切換；切換之後要等 `stage2.deliveries.startSeconds`（3 秒）才開始下一次預警，接著每 `everySeconds`（6 秒）一箱加大份。加大份的箱子比一般箱大一圈，消化要 40 秒，而且在攪拌機裡佔 2 格容量，所以容量 4 只放得下兩箱，不攔的話第三箱就會觸發胃抗議，玩家得挑著退回。兩個階段的外送參數各有一組，欄位相同（`deliveries` 與 `stage2.deliveries`），第二階段的退回傷害也是 20，所以從 60 再退回三箱就結案。階段切換會發出他專屬的 `snackStage` 事件（咖啡因 Boss 的 `bossStage` 台詞是另一句，不共用），頭上的台詞是 `boss.snack.next_stage`，名牌上的階段字樣是 `boss.snack.stage.2`。重新挑戰（強制下班）時他回到第一階段與滿預算。目前還沒有第三階段的熄燈：戰鬥在預算歸零時結束。

做這種房間時，地圖檢查會要求：有 `snack` 的 Spawn 就要有至少一個外送口（`snack-dock`）和一台攪拌機（`snack-mixer`）；外送口不能放在變體圖層（`dock-variant`），中心不能在牆裡或地圖外（`dock-wall`），從外送口中心到投料口中心的直線上不能有牆（`dock-path`，以 1 像素為步長檢查，否則從那個外送口丟出的每一箱都會撞牆消失），也不能有推箱子（`dock-box`，推箱子在遊戲裡是實心的）；每個外送口的飛行路線上至少要有一點能以直線看到部長（`dock-return`，否則從那個外送口丟出的箱子退件時都打不到他）；攪拌機的 `capacity` 不能小於加大份的 2 格（`mixer-capacity`，否則第二階段的每一箱都會讓它抗議，Boss 戰寫 4）。箱子飛行時遇到牆或推箱子的實心格子也會消失。灰盒測試房 `stomach/boss-arena` 是示範：攪拌機在正中央，四個外送口在四個角落（西北、東北、東南、西南，順時針），部長站在北邊，從夜間測試房東邊的門進來，也可以用 `?room=stomach/boss-arena` 直接開。

### 分岔輸送帶與拉桿冷卻

分岔輸送帶是 `altDirection` 不是 `none` 的 Conveyor（設計文件 7.5 節胃章的「分揀中心」，8.5 節的核心房與 8.8 節的福利「分揀熟手」都提到輸送帶切換），也就是一個可以轉向的岔路口。它永遠運轉；指向它的拉桿（或調度口）全部打開時，把箱子與營運長往 `altDirection` 送，否則往 `direction` 送。至少要有一個開關指向它，沒有的話它永遠只走 `direction`，地圖檢查會指出（`fork-switch`）；`altDirection` 和 `direction` 相同也會被指出（`fork-same`），因為拉桿轉了沒有差別。分岔輸送帶自己的 `speed` 只決定箱子從這一格離開的速度，兩條分支是各自獨立的輸送帶，所以快慢兩條路就是兩條 `speed` 不同的輸送帶。箱子離開岔路口那一刻看拉桿的狀態，已經在滑動的箱子不會改道。畫面上分岔輸送帶是偏黃的灰色，箭頭指向現在送的方向。

Switch 的 `cooldownSeconds` 大於 0 時，拉桿在變動之後這麼多秒內不接受新的一次，按 E 與被釘書針打到都一樣（釘書針只會把拉桿打開，打開也會開始計冷卻）。冷卻中按 E 沒有作用，只發出 `switchCooling`（聲音 `nope`，提示「開關還在冷卻，等一下再按」），畫面上拉桿的旋鈕變灰、底座多一條紅色細條，靠近時也不再顯示互動提示。從拉桿變動的那個 tick 算起，滿 `cooldownSeconds` 秒之後的同一個 tick 就能再按。冷卻只屬於這一趟：離開房間再回來、強制下班都會結束冷卻，拉起的拉桿本身則照舊保持。壓力板（`hold`）沒有東西可以冷卻，設了 `cooldownSeconds` 會被地圖檢查指出（`cooldown-hold`）。冷卻的長短是福利「分揀熟手」（冷卻減半）要調的參數，福利本身還沒有做。

食物箱的標籤上現在有一、二、三個小黑點，分別是小份、一般份、加大份（宵夜外送員的訂單是一般份），分揀要靠它認箱子。

灰盒測試房 `stomach/sorting-lab` 是這個謎題的示範，從攪拌機測試房東邊的門進來，過了閘門之後的門通到夜間測試房。入口東邊是一條要自己拉桿才會動的 `slow` 輸送帶（這根起點拉桿冷卻 30 秒，比四箱到岔路口的時間長，所以不能把輸送帶停下來拉開箱距、繞過岔路口），上面排著四箱，從靠近岔路口的一端起依序是大份、小份、一般份、小份，兩箱之間隔一格，每 2 秒一箱經過岔路口。岔路口直行是一條 `fast` 的短路，直通攪拌機；轉向走的是一條 22 格的 `slow` 長路，繞一圈回到投料口，要 22 秒，比最小份的 15 秒還長。攪拌機容量 3，四箱全部直行時，第四箱會把它卡住，全部吐回來。岔路口的拉桿冷卻 5 秒，所以沒辦法把某一箱單獨送上長路再馬上撥回來。小腸閘門要收 4 個小包裹，關 20 秒、開 8 秒。過關的做法是：大份和小份先直行進攪拌機，在第二箱（小份）過了岔路口之後、第四箱到之前撥一次拉桿，讓後面兩箱繞長路，這時攪拌機裡的小份已經消化完，第四箱剛好有位置；閘門在約 50 秒時收滿，門就開了。撥得太早（第二箱之前）會讓後三箱全部繞路，第四箱進來時攪拌機裡還有三箱；撥得太晚（第四箱之後）或不撥，第四箱直行進去就卡住。`test/core/fork.test.ts` 用真正的測試房逐一驗證這幾種撥法。

## 肝臟工廠與急救

肝臟章（設計文件 7.7 節）的化工廠由三個 Line 物件組成，`stage` 各選一種。`receiving` 是收貨區，畫成矩形，蓋住的格子永遠是實心的，像一排櫃檯；`alcohol` 標籤是幾杯，收貨區前幾格就擺幾桶酒精，多於格數的不另外畫。`outlet` 是出貨口，放一個點，第一產線處理完的乙醛箱從這裡附近的空地板出來。`intake` 是第二產線，畫成矩形，乙醛箱停在上面就被收下，`acetaldehyde` 標籤減一。一間房有收貨區，就必須三種各一個，地圖檢查會指出少了哪一種、多了哪一種、畫成點的矩形、整片蓋在牆上的區域，以及放在變體圖層的產線，因為酒精與乙醛記在整章的標籤上，工廠不能隨狀態出現或消失。收貨區上不能放第二產線、調度口、輸送帶、出生點、NPC、道具、床、開關或 Spawn，因為那幾格在遊戲中是實心的，地圖檢查會指出（`dock-blocked`）；觸發區可以跨過收貨區。

第一產線的速度只有一個：每小時處理 `params.json` 的 `liverRate` 杯（目前 0.6），只看章內時鐘，任何道具、工具、標籤或選項都改不了它。章內時鐘往前走的地方（對話與卡片的 `clock:` 效果、`clock_advance` 觸發區、床上等待）都會讓產線跑。一杯完全處理完才變成一個乙醛箱，所以 `alcohol` 從 2 降到 1.4 時收貨區仍是兩桶。酒精桶打不掉：釘書針打到只會彈開並提示「只能等輸送帶」，在旁邊蓋駁回印章也會顯示無效。

乙醛箱是 `boxType` 為 `acetaldehyde` 的推箱，由產線產生，不能畫在地圖上，地圖檢查會擋下。它和其他推箱一樣推、一樣被輸送帶帶走，但周圍兩格內有紅霧：營運長連續待在紅霧裡每 2 秒少半顆心，閃身也躲不掉，走出紅霧就重新計時。乙醛箱不會被調度口收下，進房時也不記得上一趟推到哪裡，每次進房都重新擺在出貨口旁邊。設計工廠房間時，請讓推到牆邊的乙醛箱還有路到第二產線，例如灰盒的 `liver/factory` 讓南牆的輸送帶把箱子送進東南角的第二產線。要等產線清空才能過的門，用 `resource` 鎖寫 `alcohol==0`。

空腹喝酒時（`fasting` 加上 `alcohol>0`，也就是修飾器 `mod.warehouse_locked`），肝醣倉庫暫停出貨：血糖不再補到 45，會一路降到 30 為止，跌破 35 時營運長頭暈冒冷汗，畫面變暗，移速慢 15%，並設定 `dizzy` 標籤，可以拿來當道具或對話的條件。倉庫恢復出貨的那一刻血糖立刻補回 45。

急救流程寫在 `content/rescue.json`，房間裡用 Trigger 開啟，`event` 選 `rescue`、`eventId` 填急救的 id。一段急救有依序要做的 `steps`、錯誤做法 `myths`、面板上列出的順序 `order`（要剛好是 steps 與 myths 的全部），可選的 `helper`（`when` 條件成立時，輪到 `step` 那一步會由別人代勞），以及完成後的 `effects`，寫法和對話的效果相同，以故事事件的身分生效。急救沒有失敗：選到錯誤做法會由朋友說明為什麼不行，選到還沒輪到的步驟會提醒先做哪一步，兩者都不會結束面板，也不會扣血或讓時間前進；做完全部步驟、按確定才關閉。面板上的文字放在字串表：標題 `rescue.<id>.title`、`rescue.<id>.prompt`、每個動作的 `action.<動作>` 與 `reply.<動作>`、`early`（`{step}` 會換成下一步的名稱）、有 helper 時的 `helper`，以及 `done`；所有急救共用的操作說明、進度與繼續提示是 `rescue.hint`、`rescue.progress`、`rescue.continue`。做完全部步驟後，按確定、按數字鍵或用滑鼠點一下面板都會關閉。`npm run check` 會指出缺少的字串、順序不完整、helper 的步驟不在 steps 裡，以及效果寫錯；地圖檢查會指出 `eventId` 不存在的急救觸發區。

## 道具與員工手冊

Pickup 是撿得起來的道具，走到旁邊按 E 或 Enter 撿起，撿起後從房間消失，離開再回來也不會再出現。`itemType` 決定撿起來的效果：

| `itemType` | 撿起來會怎樣 | `itemId` 填什麼 |
| --- | --- | --- |
| `handbook` | 員工手冊解鎖一頁，畫面跳出頁名；已經有的頁會提示「已經在員工手冊裡了」 | 手冊頁代號，必須存在於 `content/handbook.json`，例如 `caffeine` |
| `coffee` | 咖啡因殘留加一杯的量（目前 100），咖啡斗篷下一刻就生效 | 留空，或當鑰匙時填名字 |
| `file` | 沒有其他效果，適合當鑰匙 | 鑰匙名字，對應門的 `lockParam` |
| `memory` | 記憶文件（設計文件 7.4）：章節檔有 `archive` 時，先拿在手上（`archive.held` 標籤加一），要交給暫存桌才算數，睡著時再依 `archive` 換算成準備度；手上滿了就拿不起來，文件留在原地。章節檔沒有 `archive` 時只會消失並跳出提示 | 留空 |
| `meal`、`ors`、`thanks_card` | 目前只會消失並跳出提示；吃飯、電解質液與感謝卡的規則還沒做 | 留空 |

`when` 在進房時判斷一次：不成立時這一趟道具不在房間裡，下次進房再重新判斷。撿起的道具與打卡機的關係和午睡沙發相同：打卡之後才撿的道具，強制下班回到打卡機時會回到原位，因為時鐘與標籤也回到打卡當時，咖啡的殘留也一起還原；打卡之前撿的，回到打卡機後仍然算撿過。手冊頁是例外：解鎖的頁面不會因強制下班而消失，所以手冊頁撿了就不會再出現。

員工手冊的頁面寫在 `content/handbook.json`，依顯示順序排列，每頁有 `id` 與 `body`。頁名放在字串表的 `handbook.<id>.title`，`body` 列出每一段文字的字串代號，例如 `handbook.caffeine.1`，每段各自在字串表填 `fact` 欄，讓查證可以逐句對照。目前只有〈早餐與肝臟〉、〈咖啡因〉、〈睡眠債〉、〈短暫午睡〉四頁，文字取自設計文件的寫法，等內容組依核准句庫補齊與校對。缺頁名或段落文字時，`npm run check` 會指出，遊戲也不會啟動。每一頁都必須在兩種字級下放得進頁面，測試會檢查。

遊戲中按 Tab 打開員工手冊，畫面左邊列出全部頁面，還沒找到的顯示為「？？？」，W／S 翻頁，Tab 或 Esc 關閉；手冊打開時房間暫停，章內時鐘也不走。解鎖的頁面存在瀏覽器裡的跨局進度，不會因為重新開始、讀取打卡點或換章節而消失。對話裡的 `unlock:` 效果與撿起手冊頁的效果相同。灰盒章節的 `greybox/archive` 放了一杯咖啡與儲藏室的鑰匙，`greybox/storeroom` 放了兩頁手冊。

## 把房間接起來

房間本身不知道門通往哪裡。章節的串接寫在 `content/chapters/<章>.json`，檔名與裡面的 `id` 必須和地圖資料夾同名。範例（`content/chapters/greybox.json`）：

```json
{
  "version": 1,
  "id": "greybox",
  "start": "greybox/greybox-room",
  "links": [
    { "a": "greybox/greybox-room#door-s", "b": "greybox/rest-room#door-n" },
    { "a": "greybox/rest-room#door-e", "b": "greybox/brain-corridor#door-w" }
  ]
}
```

`start` 是新遊戲進入的房間。`links` 的每一項把兩扇門接在一起，寫法是「房間路徑#門的名字」，房間路徑是資料夾加檔名、不含 `.tmj`，門的名字就是 Tiled 物件的 Name 欄。兩扇門必須面對面：北門接南門、東門接西門。接好之後從任一邊走過去，都會出現在另一間房的那扇門前。

章節檔還有幾個可以不填的欄位（`carry` 與 `archive` 見下一節），序章 `content/chapters/prologue.json` 全部用上了：

```json
{
  "version": 1,
  "id": "prologue",
  "start": "prologue/lobby",
  "next": "greybox",
  "intro": "prologue.interview",
  "tools": [],
  "glucose": true,
  "links": [ ... ]
}
```

`next` 是這一章結束後接著玩的章節，必須是另一個存在的章節檔，不能是自己；沒填就回到標題畫面。`intro` 是新遊戲進入 `start` 房間時立刻開啟的對話，必須存在於對話 CSV；用 `?room=` 從別的房間開始試玩時不會播。`tools` 列出這一章開場就有的工具，目前有 `stamp`（駁回印章）與 `folder`（公文夾）；寫成 `[]` 表示一開始什麼都沒有，要靠對話的 `grant:` 效果拿到；不填這個欄位則全部工具都有，灰盒章節就是這樣。從上一章接過來的工具會一直保留。`glucose` 設為 `true` 時畫面上方出現血糖表，血糖隨營運長走動慢慢下降，低於 40 時自動補回 45，代表肝臟分解肝醣補上；開場值 55 是暫定的假設，數值寫在 `src/core/chapter/glucose.ts`。

檢查腳本對章節有幾條規定。每扇打得開的門都要接到某個地方；故意留著暫時不用的門，把 `lock` 設成 `key`、`lockParam` 留空即可。同一扇門只能接一次。整章的房間都要從 `start` 走得到：`none`、`clock`、`resource` 的門算通路，`switch` 的門在有拉桿指向它時算通路，`key` 的門在房裡有鑰匙時算通路，`lockParam` 留空的 `key` 門與只靠壓力板開的門不算。`clock` 與 `resource` 的條件實際上會不會達成，檢查腳本看不出來，要靠試玩確認。每間房都要有 PlayerStart。放在 `variant:` 圖層裡的門沒辦法寫進章節檔，所以那種門一定要設成 `lock` 為 `key`、`lockParam` 留空，或把門移到變體圖層之外。新增一個地圖資料夾時，也要在 `content/chapters/` 加上同名的章節檔，漏掉會被檢查指出。`next` 與 `intro` 指到不存在的章節或對話，也會被檢查指出。要讓新章節出現在遊戲裡，還需要程式組把它登記進 `src/app/content.ts` 的 `CHAPTER_FILES`；清單的第一章就是「新遊戲」進入的章節，目前是序章。

序章 `public/assets/maps/prologue/` 是給內容組照抄的範本章節，由 `tools/maps/make-prologue.ts` 產生，五間房依序是大廳（面試、人資發員工證、打卡機、肝與第一頁手冊）、貨運大廳（兩隻飛蟲的戰鬥教學）、倉庫（三個葡萄糖箱、繞牆的輸送帶與調度口）、會議室（董事長發駁回印章、可以試蓋的練習假人、簽了試用合約才開的東門）與夜間辦公桌（凌晨兩點的簽名，然後下班打卡結束這一章）。每一種機制都在裡面出現一次，接法就是在 Tiled 裡應有的接法；台詞是依設計文件起草的版本，內容組可以直接改寫 `content/dialogue/prologue.csv`。

## 章節的歸檔與帶入

章節結束時，這一章的標籤不會帶進下一章，下一章只從章末卡的選擇開始。章節檔的 `carry` 列出要例外帶過去的標籤名稱，這些標籤在章節結束時的值會成為下一章的起點，沒有值的標籤略過。帶過去的標籤只留一筆因果紀錄（來源是 `carry`），這一章打過的卡片不會跟著過去，所以下一章不會把同名的章首卡當成已經回答過。

章節檔的 `archive` 把「記憶文件」換算成準備度，用在設計文件 7.4 與 7.6 的「睡眠有助記憶保存」：

```json
"carry": ["exam_practice", "exam_archived"],
"archive": { "held": "memory_held", "hands": 3, "desk": "memory_desk", "total": 6, "into": "exam_archived" }
```

房間裡 `itemType` 為 `memory` 的 Pickup 每撿一份，`held` 標籤（手上的文件）加一；手上已經有 `hands` 份時撿不起來，文件留在原地，畫面提示手上滿了。手上的文件還不算數，要和暫存桌上的人對話：對話裡寫 `move:memory_held>memory_desk*100`（見「效果」一節），手上每一份在 `desk` 標籤加 100，也就是桌上一份文件是 100。桌上的文件每過一個遊戲小時淡化 5%，這個比例寫在 `content/tags.json` 裡 `desk` 標籤的 `fadePerHour`；手上的文件不淡化，所以要在忘光之前去睡。暫存桌是一個 NPC，大腦章放在海馬迴的西牆邊（`brain.desk`），避開手機精靈與文件，免得對話被搶走。

只有睡著（`bedType` 為 `sleep` 的床）時才設定 `into` 標籤，值是桌上剩下的量佔 `total` 份的百分比，再乘上夜班清潔隊的咖啡因係數：咖啡因殘留低於 15 時為 1，之後隨殘留下降，到 33 約為 0.87（`content/params.json` 的 `cafDeadZone` 與 `cafSleepK`，設計文件 9.1），若章節檔有 `climax` 而且玩家選了多喝一杯，還要再乘上它的 `archiveFactor`。床的 `requires` 決定睡不睡得成，大腦章的就寢門寫 `caffeine<50`，所以殘留 15 到 50 之間門只開一半，清潔隊人手變少。醒著沒睡就換章不會設定 `into`，仍在手上沒交出去的文件也不算。`held`、`desk` 與 `into` 都要是數值標籤，`desk` 標籤還要有 `fadePerHour`，`total` 要等於章節房間裡的記憶文件份數，`hands` 要是不超過 `total` 的正整數，`into` 要列在 `carry` 裡，檢查腳本會逐項指出。

### 章節檔的其他欄位

`climax` 是設計文件 7.4 的「最後一杯」：Boss 戰前由房間裡一張 `once` 的事件卡讓玩家選，選了多喝一杯就設定 `flag` 指定的布林標籤（來源要含 `event`）。寫法是 `"climax": { "flag": "one_more_cup", "summonFactor": 2, "archiveFactor": 0.5 }`：這一章的房間裡，咖啡因 Boss 第二階段每次召喚的腺苷數與同時存在的上限乘上 `summonFactor`，睡著時歸檔量乘上 `archiveFactor`（只能和 `archive` 一起用）。大腦章的事件卡 `climax` 放在海馬迴通往會議室的樓梯前，橫跨整層地板，所以走不到樓梯而不被問到。

`closedCases` 讓一章記住「已經結案」的敵人：`"closedCases": { "energy_seller": "seller_closed" }` 表示能量飲料推銷員被結案時設定 `seller_closed`（布林標籤），而放他的 Spawn 寫 `when` 為 `!seller_closed`，之後每次進房他都不會再出現。`caseDrops` 讓結案的敵人留下手冊頁：`"caseDrops": { "sugar_seller": "sugar_fatigue" }` 表示全糖推銷員被結案的那一刻解鎖〈糖分與疲倦〉，頁面和其他手冊頁一樣永久保留，強制下班不會收回；它和 `closedCases` 各自獨立，可以只填其中一個，敵人必須是可結案的種類，頁面必須在 `content/handbook.json`，否則 `node tools/check-maps.ts` 與開機都會擋下。敵人檔裡 `archetype` 填 `manager`（主管，例如胃章的加大份推銷員 `large_seller`，業績 12）的敵人正面有盾：盾蓋住他面向的 120 度，釘書針和公文夾前兩下輕揮從正面打來都被擋下，沒有傷害、沒有駁回量表、沒有命中停頓，只有一聲擋下的悶響、幾片紙屑和「正面有盾：繞到背後，或用公文夾重擊」的提示（連續擊發時這張便條只保留一張、重新計時，不會疊起來）。破防有三種，設計文件 5.3 節列為繞背、反彈與重擊：從背後或側面（超出那 120 度）打來的照常算傷害；被公文夾退件彈回去的子彈打在盾上，以及公文夾三段揮擊的第三下（傷害 4，重擊）都會破防，這一下照常算傷害，他被震暈 1.2 秒、正在準備的盾擊取消，盾倒下 3 秒（從破防那一刻算起，暈眩包含在內）。駁回印章不是丟出去的東西，不受盾影響，一個滿格量表就能結案。他只在待命時轉向（走路，或進到範圍後原地轉向營運長），每秒最多 90 度，要面向營運長（30 度內）才出招，從預警開始到出招後的停頓結束都不轉向，所以閃身穿過他的招式，或貼近繞圈，都能繞到他背後。他的招式是一級預警的盾擊，扣半顆心，可以閃身，也可以退件。除了重擊的傷害 4（`FOLDER.damage`，設計文件 6.1 定下的）以外，以上數字都在 `src/core/combat/frames.ts` 的 `MANAGER`，是待試玩的佔位。強制下班或重生會讓他的盾立起、面向南方，破防的倒數不會帶進下一次。敵人檔裡飛行型的敵人可以填 `"throws": "can"`，讓牠丟出的是罐裝能量飲料而不是紙張：罐子要格擋或閃開，打中的人不扣心，而是咖啡因殘留加 150（`content/params.json` 的 `energyDrink`），殘留已超過 300 時推銷員會說出 Disco 那句台詞。填 `"throws": "tea"` 則丟出全糖手搖飲（胃章節的全糖推銷員 `sugar_seller`），一樣不扣心、閃避會拒絕、格擋接得住，喝到的話營運長進入 45 秒的全糖倦怠霧：移動慢 15%（和其他減速一起受設計文件 5.1 的上限約束，而霧單獨就達到上限，所以霧中其他減速不再疊加），畫面只留營運長周圍一小圈看得清楚，HUD 顯示剩下的秒數。再喝一杯會從 45 秒重新算。倦怠霧跟著營運長走過門，打卡不會清掉，強制下班或讀取打卡點則會清掉。外層卡片設下的 `sugar_fatigue` 標籤不會帶來這層霧。灰盒測試房 `stomach/mixer-lab` 裡有一個全糖推銷員，東南角還有一個加大份推銷員。

`partner` 指定這一章帶著哪位夥伴，目前有 `"partner": "chairman"` 和 `"partner": "logistics"`，章節只能帶一位，兩者都用 L 或滑鼠右鍵發動。`chairman` 舉起董事長的「畫大餅」護盾：護盾罩住營運長 2.5 格的範圍 4 秒，擋掉範圍內飛來的投射物（不擋範圍攻擊與近戰），然後冷卻 12 秒，冷卻是每進一間房重新計算。範圍與持續時間都乘上 S，S 由睡眠決定，所以睡得少的日子護盾又小又短，畫面上的狀態列會顯示「大餅 ×S」。基本數值寫在 `src/core/combat/pie.ts`，是等試玩調整的暫定值。

`logistics` 是胃章的胃物流主管（設計文件 6.2 節），技能「強制卸貨」：往營運長瞄準的方向（四捨五入成上下左右四向，斜著瞄時橫向優先）吐出一塊酸液，從身前 8 像素起、長 3 格、寬 1.5 格，躺在地上 3 秒，冷卻 9 秒（從吐出那一刻算起，進新房間重新就緒）。酸液留在吐出的位置，營運長走開它不跟著走。酸液裡的一般敵人（`defeatable`，不含 `cheers` 與 Boss）每半秒損失 1 點 performance，吐出的那一刻就算第一次，並且每一刻被沿著酸液方向推開，推的速度比任何走過來的敵人都快；被釘住的敵人照樣受傷，但不會被推。酸液不是投擲物，所以不理會管理型敵人的盾，免疫與重組類敵人（設計文件沒有給它們酸液的解法）、乾杯小孩與 Boss 一律不受影響。受傷中的營運長不能吐，強制下班會收起酸液並讓技能重新就緒。酸液的大小、傷害與推力是等試玩調整的暫定值，設計文件只定了 3 秒和 9 秒，數值寫在 `src/core/combat/unload.ts`。設計文件的謎題用途（酸液融掉擋路的食物塊）尚未實作，第 15 項事實查證也還在等待，所以字串的 `fact` 目前是空的。

這一章的房間靠北門與南門疊成四層樓：教學室、辦公室、海馬迴、會議室與屋頂依序往上，`links` 把下一層的南門接到上一層的北門，大廳、總務處與教學室之間仍然走東西門。

## 巡視的房間

學期模式的巡視（設計文件 8.5）用的是一般的章節，只是章節檔多一個 `patrol` 欄位（`brain`、`immune`、`stomach`、`liver`、`gut` 其中之一）。有這個欄位的章節不跑章內時鐘，房間是進房那一刻標籤的快照，所以房間的變體與 Spawn 的 `when` 讀到的是學期當天的狀態，例如大腦休息室的腺苷用 `sleep_debt>=0.5`、`sleep_debt>=2`、`sleep_debt>=4` 三組各放兩隻。依賴時鐘才會動的機制在巡視裡不會自己動，這一點要在房間裡處理掉：肝的產線不會把酒精轉成乙醛，所以 `patrolTags`（`src/core/chapter/patrol.ts`）在進房時先把當天的工單換成 2 到 4 箱乙醛，核心房的出口旁直接就有箱子。

一個樓層的巡視是 `public/assets/maps/patrol-<樓層>/` 底下的四間房，由 `tools/maps/make-patrol.ts` 產生，不要手改 `.tmj`。房間的順序與名字是約定：`lobby` 是入口，中間兩間挑戰房，最後一間必須叫 `core`，因為核心目標只在 `<章節>/core` 這間房裡判斷（`patrolGoals`）；入口大廳放該層的器官員工，對話以 `patrol.<樓層>.lobby` 為 id，依標籤講今天的狀況。每個核心房東牆有一個電梯：一個 `Trigger`，`event` 是 `end`、`eventId` 是 `elevator`、`once` 關掉，踏上去就結束巡視並結算評等，畫面會把它畫成灰色的樓層平台與上下箭頭。

核心目標由 `patrolGoals` 讀房間的狀態決定：大腦是休息室裡所有會黏人的敵人都已被鎖住，肝是當天的乙醛箱都已送進第二條線。大腦用的是 `Pen`（休息區）物件類別：一個矩形，閒置中的黏人敵人，也就是腺苷，中心點一進去就被鎖成結案狀態，不會重組，也不會再黏上營運長，已經黏在營運長身上的不受影響。支線目標是一個叫 `patrol_side` 的布林標籤，由巡視房間裡的 NPC 對話用 `tag:patrol_side` 設定；每層放在第二間挑戰房的遠角，前面站兩個守衛。要加另一層的巡視，就是新增章節檔與四間房、在 `src/app/patrol.ts` 的 `PATROL_CHAPTERS` 登記樓層，並在 `patrolGoals` 補上那一層的核心目標；沒有登記的樓層學期模式仍用抽樣技能決定評等。

評等的數值在 `src/core/semester/patrol.ts`：核心目標沒做到最高 C，做到是 B，被打不超過 `HITS_FOR_A`（2）次升一級，支線目標升一級。被打指失去心與腺苷黏上身，乙醛霧氣不算。放棄或被強制下班算失敗。這些數值都是暫定的，調整時一起看 `test/core/patrol.test.ts` 的評等表。

開發時用 `?room=patrol-brain/core&tags=sleep_debt:3` 可以直接看核心房，但這條連結不是巡視場次，所以畫面上會有章內時鐘，肝的工單也不會先換成乙醛；要看完整的巡視，從標題進「學期模式」，選層之後就會進入入口大廳，按 Esc 可以放棄。

## 在瀏覽器試玩

在專案根目錄執行 `npm install` 與 `npm run dev`，用網址直接進指定的房間：

```
http://localhost:5173/?room=greybox/rest-room&tags=caffeine:50
```

`room` 是房間路徑；`tags` 是進房時身上的狀態標籤，數值標籤寫成 `名稱:數值`、布林標籤只寫名稱，用逗號隔開；`halves=2` 讓營運長只剩 2 個半顆心，方便測試強制下班；`gauge=100` 讓駁回量表直接是滿的。這些參數只在開發版有效，正式版會忽略。房間裡按 F1 可以看到碰撞框。

## 提交前

執行 `npm run check`（只想檢查地圖時執行 `node tools/check-maps.ts`，只檢查資料檔時執行 `node tools/check-content.ts`，只檢查對話時執行 `node tools/check-dialogue.ts`，只檢查卡片時執行 `node tools/check-decks.ts`）。通過時最後一行是 `0 problem(s)`。有問題時每一行是一個問題，開頭是檔名，接著是物件編號與原因，例如：

```
public/assets/maps/brain/coffee-room.tmj 物件 #4（Door）：門「door-e」沒有接到任何房間，卻打得開（lock 為 none）；請在章節檔連起來，或把 lock 設成 key、lockParam 留空
```

合併到 `main` 之前，GitHub 上的檢查會跑同一套規則，沒通過不能合併。

遊戲的字型只收錄內容用得到的字，所以字串或對話用了一個新字時，`npm run check` 會回報「字型子集缺少內容用到的字」。這時執行 `python tools/fonts/build_fonts.py`（需要 Python 3.12 與 `pip install fonttools brotli`，第一次會下載原始字型，約需兩三分鐘），把 `public/assets/fonts/` 裡變動的檔案一起提交即可：基本字型與 `extra/` 切片是一起產生的，只提交其中一部分、或把切片還原成舊版（即使看起來只差時間戳記），會讓同一個字被兩邊重複宣告，`npm run check:art`（`verify` 已包含）的字型檢查會失敗。建置要跑到結束，不要用管線截斷輸出。重新產生後還是缺的字，代表字型本身沒有這個字，請改用別的字。

## 對話

對話寫在試算表裡，匯出成 UTF-8 的 CSV，放進 `content/dialogue/`，一個檔案可以放很多段對話，同一個 `dialogueId` 不能出現在兩個檔案。第一列是表頭，欄位名稱與順序固定：

| 欄位 | 內容 |
| --- | --- |
| `dialogueId` | 這一段對話的名字，Tiled 的 NPC 與 Trigger 就是用它接上；同一段對話的每一句都填同樣的名字 |
| `order` | 這一句在該段對話裡的順序，從 1 開始的整數，同一段裡不能重複；播放順序看 `order`，不看列在檔案裡的先後 |
| `speaker` | 說話者代號，必須登記在 `content/speakers.json`；玩家的選項一律寫 `operator` |
| `expression` | 表情，對應立繪 `public/assets/portraits/portrait-<說話者>-<表情>.png`；玩家的選項可以留空 |
| `text` | 台詞或選項文字；有逗號或換行時，整格要用雙引號包起來 |
| `condition` | 條件式，語法與 Tiled 的 `when` 相同；不成立時這一句被略過，留空表示一定顯示 |
| `effect` | 這一句出現時（選項則是被選中時）發生的事，多個效果用分號隔開，寫法見下方 |
| `next` | 這一句之後接哪裡：另一列的 `order`，或 `end` 表示結束；留空就接下一列 |
| `fact` | 台詞若含生理說法，填衛教查證表的條目編號；查證尚未完成的填 `pending:編號`；也可以填 `general`，意思與標籤字典和字串表裡的 `general` 相同；沒有生理說法就留空 |

範例（`content/dialogue/greybox.csv` 中腦的簡報）：

```csv
dialogueId,order,speaker,expression,text,condition,effect,next,fact
greybox.brain.briefing,1,brain,normal,早安，營運長。今天的待辦有點多。,,,,
greybox.brain.briefing,2,brain,surprised,你的黑眼圈比昨天深了。,sleep_debt>=2,,,
greybox.brain.briefing,3,brain,normal,先從哪一件開始？,,,,
greybox.brain.briefing,4,operator,,先趕報告。,,tag:deadline;clock:30,7,
greybox.brain.briefing,5,operator,,先去補眠。,,clock:20,8,
greybox.brain.briefing,6,operator,,晚點再說。,,,end,
greybox.brain.briefing,7,brain,warning,好。截止時間逼近了，記得存檔。,,,end,
greybox.brain.briefing,8,brain,sleepy,好。睡醒再說。,,,,
```

### 一段對話怎麼走

對話從第一句開始往下走。說話者的句子顯示在對話框裡，按 E、Enter、J、空白鍵、K 或滑鼠左鍵繼續（互動、攻擊與閃身的按鍵都算確認）。連續 2 到 3 列 `speaker` 為 `operator` 的列是一組玩家選項，會以便利貼從畫面右側滑出；用 W、S 移動、再按確認鍵，或直接按 1、2、3，也可以用滑鼠點選項（選項出現時，滑鼠只有點中便利貼才算數，點在空白處不會送出目前選中的選項）。選了之後接著走那個選項自己的 `next`，沒填就接在這一組選項後面的第一列。`next` 只能指向比自己大的 `order`，所以每一段對話一定會結束；它也不能指向一組選項的中間。上面的範例裡，第 4 列選了之後接第 7 列，第 5 列接第 8 列，第 6 列直接結束，所以第 7 列要自己寫 `end`，否則會接著念第 8 列。對話結束後的 0.5 秒內互動鍵不起作用（這段時間內再按會重新計時，要停手 0.5 秒才恢復），HUD 的互動提示也暫時不顯示，避免連按 Enter 讀完對話時，最後多按的一下又和同一個 NPC 重新開始對話。

條件讀的是當下的標籤。說話者的句子條件不成立就略過，接著看下一列；選項條件不成立就不出現；一組選項全部不成立，整組略過；整段都被略過時，對話不會開啟。選項生效之後的下一句，看得到那個選項剛設定的標籤。

### 效果

`effect` 可以寫好幾種，用分號隔開，依序生效：`tag:名稱` 把布林標籤設為成立；`tag:名稱=數字` 把數值標籤設為該值；`tag:名稱+數字` 把數值標籤加上該值；`move:甲>乙*倍數` 把數值標籤甲清空，每一單位在乙加上倍數，例如 `move:memory_held>memory_desk*100` 把手上的文件放到暫存桌上，甲與乙都要是數值標籤、彼此不同、對話可以設定，也不能是酒精、咖啡因、血糖或睡眠債；`clock:分鐘` 讓章內時鐘前進，說話是花時間的；`unlock:手冊頁代號` 解鎖一頁員工手冊；`grant:工具` 交給營運長一項工具，目前有 `grant:stamp` 與 `grant:folder`；拿到印章時駁回量表直接填滿，可以馬上試蓋，拿到公文夾時只是放進口袋，玩家按 F 才會換上。`grant:` 只能寫在對話與事件卡，章首卡與章末卡不能用。對話只能改標籤字典裡來源含 `event` 或 `chapter` 的標籤，來源只有 `card` 或 `rule` 的標籤（例如早餐）由卡片或規則算出來，對話不能直接設定。咖啡因的來源含 `chapter`，因為房間裡的咖啡道具會加它，所以對話也可以寫 `tag:caffeine+100`，例如推銷員遞上一杯咖啡。名稱以 `mod.` 開頭的修飾器是由標籤條件算出來的，同樣不能設定，要改它所依據的標籤。每個標籤的變動都會記進因果紀錄，寫明是哪一段對話的哪一句造成的。喝酒永遠不是戰鬥增益（設計文件 5.1）：任何效果都不能寫 `tag:alcohol=數字`，酒精只能由肝臟產線處理掉；加酒精的那一格效果，也不能同時發工具、設定睡眠債，或增加咖啡因與血糖。對話、卡片與急救的檢查都會擋下這兩種寫法。

### 說話者與兩種版面

`content/speakers.json` 登記每個說話者的 `style` 與 `portrait`。每個說話者還要在 `content/strings/zh-TW.json` 有一則 `speaker.<代號>` 的名牌文字，少了的話 `node tools/check-content.ts` 會報錯。`operator` 是玩家選項專用的代號，不能登記。

`style` 為 `box` 的說話者使用畫面下方的對話框，左上角有名牌，立繪站在對話框左上方，下緣被框蓋住一截。`style` 為 `memo` 的說話者用在肝，肝不說話，沒有對話框，台詞寫在畫面中央偏右的一張便利貼上，立繪站在畫面左下。立繪每次只顯示正在說話的那一位；玩家選項出現時，對話框裡仍是上一句說話者的台詞。`portrait` 為 `false` 的說話者不需要立繪檔。

### 長度限制

對話框每行最多 30 個全形字、最多 3 行。玩家選項的便利貼最多 2 行，100% 字級每行 17 字，125% 字級每行 14 字，所以 28 字以內在兩檔字級都放得下。肝的便利貼最多 3 行，100% 字級每行 13 字，125% 字級每行 10 字，所以 30 字以內都放得下。斷行規則和遊戲相同，例如收尾標點不落在行首，所以標點多的句子可能比字數看起來更早換行。兩種便利貼的寬度是暫定值，美術確認前可能調整。

### 宿主的名字

宿主（公司營運的那位學生）的名字由玩家在新遊戲開始前決定，預設是「小晨」，之後也可以在標題畫面更改。所以內容裡不要直接寫「小晨」，要寫 `{host}`，遊戲畫出文字時會換成玩家取的名字，例如：

```csv
prologue.brain.wake,1,brain,normal,{host}又熬夜了。,,,,
```

`{host}` 可以用在對話 CSV 的 `text` 欄，以及 `content/strings/zh-TW.json` 裡卡片、手冊、HUD 與便利貼的文字，一句裡寫幾次都可以。

- **長度**：名字最多 6 個字。對話、卡片與手冊的長度檢查一律把 `{host}` 當成 6 個全形字來量，所以用「小晨」放得下、換成 6 個字就超出的句子會被擋下，請預留空間。
- **報告不能用**：結算報告依設計文件第 3 節一律稱「宿主」、寫給營運長，所以 `report.` 開頭的字串不能寫 `{host}`，`npm run check` 會擋下。
- **拼錯會被抓到**：`npm run check` 會檢查字串表與對話裡所有 `{...}` 佔位符，不認得的（例如打錯成 `{hots}`）會報錯，不會直接顯示給玩家。程式新增其他佔位符時，要登記在 `tools/check-content.ts` 的 `PLACEHOLDERS`。

### 檢查

`node tools/check-dialogue.ts`（`npm run check` 已包含）用遊戲讀檔的同一支程式讀 CSV，所以它放行的檔案遊戲一定讀得進去。它檢查表頭與欄位數、`order`、條件式與效果的寫法、`next` 的目標存在且只往後、每組選項是 2 到 3 列、每一句都有辦法走到、說話者已登記、立繪檔存在、文字放得進版面，以及 `unlock:` 指到的手冊頁存在。有任何一列出問題，整段對話都不會載入，遊戲啟動時也會直接停下並列出問題，所以不會有只剩一半的對話；欄位數不對的那一列也一樣，整段對話會被整個略過，不會再連帶報出一串「找不到下一句」。訊息裡的列號和試算表顯示的一致，空白列也算一列。地圖檢查確認 Tiled 裡寫的 `dialogueId` 存在於某個 CSV，遊戲啟動時也會對每張房間地圖再確認一次，所以舊的打包檔不會等到玩到一半才出錯。

`npm run check:release` 多擋一項：`fact` 還是 `pending:編號` 的句子，表示衛教查證還沒完成，不能發行。目前沒有任何工作流程會自動執行它，發行前要手動跑一次。字串表 `content/strings` 裡的 `pending` 標記不在這個檢查的範圍內。

### 目前還沒有的

台詞整句直接顯示，沒有逐字出現的效果。同一個 tick 只會開一段對話；同時踩到兩個對話觸發點時，後一個被丟掉；如果它是只觸發一次的觸發點，會還回來，離開再踩進去就能觸發。同理，整段都被條件略過、沒有開起來的對話，也不會用掉它的觸發點。每一句出現後的前 12 個 tick（0.2 秒）按鍵不算，避免戰鬥中按住的鍵把第一句直接跳過，這個時間是暫定值，要看試玩的感覺再調。

## 卡片

每一章的外層卡片寫在 `content/decks/<章>.json`，檔名與裡面的 `chapter` 都要和章節檔同名。卡片主要分兩種（另有章末卡，見本節後段）：章首卡在新遊戲進入第一間房之前依序翻開，決定這一章開局有多糟（例如昨晚幾點睡、早上有沒有喝咖啡）；事件卡在章節中途由 Tiled 的 Trigger 翻開，`event` 選 `card`、`eventId` 填事件卡的 id。範例（`content/decks/greybox.json` 的一部分）：

```json
{
  "version": 1,
  "chapter": "greybox",
  "opening": [
    {
      "id": "morning_coffee",
      "options": [
        { "id": "drink", "effect": "tag:caffeine=100" },
        { "id": "skip", "effect": "" }
      ]
    }
  ],
  "events": [
    {
      "id": "group_chat",
      "options": [
        { "id": "rewrite", "effect": "tag:deadline;clock:60" },
        { "id": "office_hour", "effect": "tag:stress+10" }
      ]
    }
  ]
}
```

章首卡最多 3 張，每張卡有 2 到 3 個選項。卡片 id 在整個卡組裡不能重複（章首卡與事件卡共用一套 id，因為卡面文字以 id 為鍵），同一張卡的選項 id 也不能重複。`effect` 的寫法與對話相同，留空表示這個選項不改變任何狀態，但選擇本身仍會記進因果紀錄，結算報告才知道玩家選了什麼。章首卡只能設定標籤字典裡來源含 `card` 的標籤，事件卡只能設定來源含 `event` 的標籤。

卡面文字放在 `content/strings/zh-TW.json`：題目是 `deck.<章>.<卡>.title`，每個選項的名稱是 `deck.<章>.<卡>.<選項>`，名稱下方的說明是 `deck.<章>.<卡>.<選項>.note`。題目最多 2 行，選項名稱最多 2 行，說明最多 4 行，在 100% 與 125% 字級都要放得下。選項說明是玩家做決定時唯一的線索，請寫出這個選擇在章節裡會造成的結果，例如「睡眠債 2 小時：走廊多兩個腺苷通風口」。

章首卡畫面可以用 W、S、A、D 或方向鍵移動，按 E、Enter、J 或空白鍵確定，也可以直接按 1、2、3 或用滑鼠點卡片。事件卡出現時房間與章內時鐘都會停住，用 W、S 移動、確認鍵確定、1 2 3 直接選，或點卡片；點在卡片以外的地方不算數。和對話一樣，卡片出現後的前 12 個 tick 按鍵不算。帶有事件卡的 Trigger 預設只觸發一次。

章內時鐘在探索時會自己走，現實 55 秒是遊戲裡 1 小時（`content/params.json` 的 `exploreSecondsPerHour`）；對話與事件卡打開時時鐘停住。咖啡因殘留隨時鐘以 5 小時半衰期遞減（`halfLife`），殘留 50 以上時腺苷完全看不到營運長，不會飄過來也不會黏上，25 到 50 之間只在 2 格內察覺，25 以下恢復正常。

卡組還可以有第三種卡：章末卡寫在 `closing`，最多 3 張，寫法與章首卡相同，也只能設定來源含 `card` 的標籤。章節結束時（睡覺或 `end` 觸發點），章末卡在標題「下班之後」下依序翻開，選擇的效果帶進 `next` 那一章的開場。序章用它問「今晚幾點睡？」，答案就是灰盒章節的睡眠債。下一章的章首卡裡，已經在上一章章末回答過的同一張卡（卡片 id 相同）會被略過，所以灰盒章節接在序章後面時只問咖啡，沒有經過序章、直接進灰盒時兩張都問。章節一結束、章末卡翻開之前就會存檔，章末卡回答完再存一次，這時按標題畫面的「繼續」會從下一章的章首卡開始。章末卡還沒回答就關掉遊戲時，「繼續」同樣進下一章，不會回到剛結束那一章的打卡點；沒回答的章末卡如果也在下一章的章首卡裡，會在那裡再問一次。最後一章結束時則清空存檔。

`node tools/check-decks.ts`（`npm run check` 已包含）用遊戲讀檔的同一支程式讀卡組，檢查格式、id、效果寫法、卡面文字是否存在與放得下，並把每一種章首卡組合實際帶進章節：每間房都要進得去，而且在等待 24 小時之內，至少有一張 `bedType` 為 `sleep` 的床的 `requires` 會成立；每一張事件卡的每個選項也會疊在每種組合上再試一次。任何一種組合讓章節無法結束，檢查就失敗。檢查同時列出每種組合的敵人數、董事長精神 P 與「壓力」，以及最難組合比最簡單組合難多少，設計文件的目標約 30%；這個數字只記錄、不會讓檢查失敗。壓力是敵人數除以 P，其中會黏人的敵人（腺苷）按咖啡因斗篷打折：從開場到 23:00 的每一分鐘，看它當下的偵測距離佔正常距離的比例（看不見算 0，只在 2 格內察覺算 2/5），取平均。早上一杯咖啡讓腺苷在這一天平均只看得見約 47%。檢查也列出每個選項的影響，也就是含有該選項的組合平均壓力，用來找出是哪一張卡拉開差距。壓力沒有計入 P 對心數上限的影響（設計文件 5.6），那一項只在進房時由 `heartCap` 算出，檢查不會去玩房間。地圖檢查確認 Trigger 寫的事件卡存在於該地圖資料夾那一章的卡組，遊戲啟動時也會再確認一次。

## 尚未驗證的事

Tiled 在「另存新檔」時是否會改寫範本裡圖塊集的相對路徑，目前沒有在 Tiled 裡實際確認。範本與正式房間在同一層資料夾，直接複製檔案不會有路徑問題；若在 Tiled 裡另存新檔後圖塊消失，請改用檔案總管複製範本。
